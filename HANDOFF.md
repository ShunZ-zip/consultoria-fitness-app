## 2. Stack e convenções (para não reaprender)
Next.js 16 (App Router, Turbopack) + TypeScript 7 + PGlite (PostgreSQL embutido em `data/pglite`) + zod 4 + Vitest 5. Sem ORM: SQL direto via `ctx.db.query`.

- `src/server/schema.ts`: `SCHEMA_SQL` + `MIGRATION_2..7_SQL` (aditivas e idempotentes, executadas em `db.ts` ao abrir). **Para mudar o banco: nova `MIGRATION_N_SQL` e registrá-la em `db.ts`.**
- Handlers por entrega: `handlers.ts` (1–2: auth, convites, treinos, versões, modelos, volume, permissões, registros, comparação), `handlers3.ts` (evolução, último treino), `handlers4.ts` (mídia, avaliações, check-ins, chat), `handlers5.ts` + `payments.ts` (cobrança). Cada handler é `route(async (ctx) => ...)` (`http.ts`): recebe `Request`, devolve `Response`; exige `Content-Type: application/json` em escritas.
- Rotas Next são finas: `src/app/api/**/route.ts` chamam o handler. Foram geradas por scripts Python (padrão: `export const GET = async (req, ctx) => handler(req, await ctx.params)`). Ao criar um handler novo, criar a rota correspondente.
- Regras puras ficam em `src/lib/*` (volume, evolution, syncQueue, permissions, media, assessment, checkin, billing, finance, format) e têm testes unitários.
- Autorização central: `requireActor(ctx, role?)`, `loadVersion`, `assertStudent`, `requirePerm`. Auditoria: `audit(db, actor, action, detail)` → `audit_log`.
- Testes chamam os handlers diretamente (`tests/helpers.ts`: `call(handler, {body, cookie, params})`). Banco em memória (`DB_DIR=memory`, `tests/setup.ts`). **Sempre incluir testes de isolamento** (aluno×aluno, consultoria×consultoria) e rodar uma "mutação" rápida (quebrar a regra de propósito, ver o teste falhar, restaurar).
- Validação por HTTP contra o servidor real: `npm run validate` (`scripts/validate.ts`; cobre entregas 1–5 + senha, 96 verificações; exige servidor rodando).
- Armadilhas do ambiente: (a) heredocs longos no Bash às vezes quebram — use a ferramenta Write para arquivos e Python para patches (`assert count == 1`); (b) o servidor de desenvolvimento **precisa ser reiniciado** quando mudam `src/lib/*` usados no servidor ou migrações (o módulo/DB ficam em memória); (c) `rm -rf data/pglite` + `npm run seed` recria o banco de demonstração; (d) o painel do navegador acelera/atrasa animações: ao tirar captura, esperar alguns segundos; (e) o `preview_start name=dev` usa `.claude/launch.json`.

## 5m. Rotinas com metadados (issue #12, 3ª ideia adotada)
**O que é:** uma **rotina** agrupa os treinos de UM aluno e leva metadados: nome, **objetivo** e **nível** (listas propostas em `src/lib/routine.ts`), **orientações gerais** (o aluno lê), **início e fim** (período, **não é agenda**: sem horários), **mostrar para o aluno** (Sempre / Só a partir da data de início), **arquivar ao vencer** e **mostrar o tempo do treino**. O modelo de treino/versões **não mudou**: `programs.routine_id` é opcional, então treino sem rotina continua igual e sempre visível. **Não feito de propósito:** "permitir PDF" (não existe exportação) e a data de fim não bloqueia nada além da visibilidade.
**Regras (puras, `lib/routine.ts`):** o aluno só vê rotina **ativa**; excluída ou arquivada some; "só a partir do início" esconde até o dia do início; venceu + "arquivar ao vencer" conta como arquivada **sem tarefa agendada** (calculado na leitura, pelo dia civil de Brasília); no dia do fim ainda vale. **Excluir só oculta** (treinos, versões e registros ficam; o personal continua vendo). **Restaurar** uma rotina já vencida com "arquivar ao vencer" desliga essa opção (senão arquivaria de novo), com aviso e auditoria. A mesma regra existe em TypeScript (`visibleToStudent`) e em SQL (`listVersions`), cobertas por testes. O filtro é de **exibição**: o aluno ainda abre um treino por link direto e o histórico/evolução dele não é afetado.
**Servidor:** `MIGRATION_12_SQL` (`routines`, `programs.routine_id`), `handlers11.ts` (`GET/POST /api/students/[id]/routines`, `PUT /api/routines/[id]`, `POST /api/routines/[id]/status` {active|archived|deleted}, `POST /api/versions/[id]/routine` para mover treino, `GET /api/me/routines` visão do aluno), `createVersion` aceita `routineId` (rotina de outro aluno, de outra consultoria, inexistente ou excluída = 404), `getVersion` devolve `routine {id,name,showTime}`, `listVersions` devolve `routineId/routineName` e filtra para o aluno. Tudo escopado pela consultoria; aluno 403 nas rotas do personal; ações auditadas (`routine.create/update/archive/delete/restore/move_workout`).
**Telas:** personal, perfil do aluno: seção **Rotinas** (abas Ativas/Arquivadas/Excluídas com contadores, "+ Criar rotina", Editar, **+ Treino** (abre o editor já com a rotina), Arquivar/Restaurar/Excluir, motivo de o aluno não ver) e, em cada treino, um seletor para **mover de rotina**; editor de treino: campo **Rotina (opcional)**. Aluno: `/aluno` agrupa por rotina (nome, objetivo · nível · período, **Orientações gerais** recolhível) e "Outros treinos" para os sem rotina; o diálogo de conclusão e o resumo respeitam "mostrar o tempo do treino".
**Testes:** `tests/routine-lib.test.ts` (5) e `tests/routine.test.ts` (9; mutações da visibilidade e do escopo detectadas) e 5 verificações no `validate` (agora **109**); suíte **312 testes (24 arquivos)**. Verificado no navegador (desktop e 375 px): criar com validação, preencher, ver como o aluno, editor com a rotina escolhida, rascunho salvo na rotina. Corrigido na verificação: caixas e botões de opção esticados pelo estilo global de campos (`.pk-check`, também vale para o "favoritar" do seletor de exercícios).
**Seed:** Aluno Um tem a rotina "Mesociclo 1" (Hipertrofia, Intermediário, orientações, período de 70 dias) com o treino dele. **Não verificado:** conclusão offline em treino de rotina com "tempo oculto" no navegador; rotinas no tema escuro.

## 5n. Aluno: Iniciar treino e atalho da demonstração (issue #12, 4ª ideia adotada)
**Fluxo (`/aluno/treino/[id]`):** ao abrir um treino atual o aluno cai no **modo visualização** (faixa azul "Iniciar treino", campos desativados, só a prescrição). **Iniciar treino** cria o registro na hora (id gerado no aparelho, **sem precisar de rede**) e libera os campos; aparece a barra **"Treino em andamento · m:ss"** (cronômetro; oculto se a rotina desliga "mostrar o tempo do treino") com **Concluir treino**, que abre o diálogo da §5j. O "Parabéns" só aparece até **6 h** depois de concluir (`isFreshFinish`); depois a tela volta ao modo visualização com campos em branco (antes ficava para sempre com os valores antigos). Versão anterior continua só leitura. O registro ainda nasce no primeiro "Salvar" se alguém chegar a uma sessão sem passar pelo botão (compatibilidade).
**Hora real de início:** `POST /api/versions/[id]/logs` aceita `startedAt` (ISO) e o guarda se estiver entre **24 h atrás e agora** (futuro vira agora; mais antigo que 24 h é ignorado; formato inválido 400); reenviar o mesmo id nunca muda o início já guardado. **Atalho da demonstração:** cada exercício tem, à direita do nome, o botão **Demonstração** (ícone de play, `aria-expanded`); só ao tocar carrega a mídia (3D, vídeo do YouTube ou do personal) via `MediaPanel`. **Decisão:** sem miniatura automática do YouTube, para não enviar o IP do aluno a terceiros antes de ele pedir; a miniatura de verdade fica para quando houver imagens próprias.
